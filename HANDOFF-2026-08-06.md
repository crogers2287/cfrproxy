returned empty, and retries landed in the same load window.

## MISTAKES I MADE — DO NOT REPEAT

1. **`LLAMA_ARG_THINK=none` was wrong.** It disables llama.cpp's tag parser, which let the
   template's prompt-side `</think>` leak into `content` as an **orphaned closing tag** with
   no opener. That broke message parsing in a NEW way. **The correct setting is the default
   (`auto`) — do not set `LLAMA_ARG_THINK`.** Verified: default gives clean content, 0 stray
   tags, `reasoning_content` empty.
2. **`LLAMA_ARG_THINK_BUDGET=256` also injected an orphaned `</think>`.** Removed.
3. **I restarted llama-swap ~5x in 20 min while the user was testing.** Every restart unloads
   the model → the user's next attempt hit a 57 s cold start → "empty content". **Several of
   the failures the user reported were caused by me.** Warm the model and LEAVE IT ALONE
   before asking the user to test.
4. **I tested `:9069` directly for hours** while the harness goes through cfrproxy `:8420`.
   That is why the real bug went unfound so long. **Always test the full path.**
5. **A YAML edit via Python string-slicing corrupted config.yaml** (duplicate
   `deepseek-v4-flash-batch` key, restart-looped 106 times). Use line-based insertion and
   **`yaml.safe_load` BEFORE restarting the service.**
6. **`cp -u` silently truncated a 46 GB model part** (mtime comparison skipped it). Always
   verify `stat -c%s` source vs dest after staging.
7. **pkill self-kill twice** (exit 144) — the literal pattern appearing anywhere in the
   command line matches your own shell. Use `pgrep -x <procname>` or kill by PID.
8. **A GPU-clear guard that waited for ZERO GPU processes never fired** because MemPalace
   holds ~850 MiB permanently. Production sat down 33 min for nothing. Wait for
   `pgrep -x llama-server`, not for an empty GPU.
9. **IQ3_S (109 GB) was the wrong pick** — I sized it against `/dev/shm` capacity when the
   real constraint is **VRAM after compute buffers** (~50 GB usable for weights). It OOM'd at
   ncm 22 and gave no timings. Deleted. The `--tensor-split` comment in
   `run-ds4-llamacpp.sh` explains why: **it is a LAYER-COUNT ratio, not a byte budget**, and
   the expensive layers are all at the tail.
